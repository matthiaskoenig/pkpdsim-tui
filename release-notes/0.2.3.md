# Release notes for pkpdsim-tui 0.2.3

The touch of the table, which 0.2.2 took: a finger of the tracker is in the pixels of the glass again. The simulator moves out of the table as well, so the two are the two apps they always were.

## A finger is on the glass, not on the drawing

0.2.2 drew every table on one surface, 1920 by 1080, and scaled it to the glass. A finger of the tracker arrives as a fraction of the sensor and has to be turned into a point of the page before the browser can be asked what is under it, and that point was multiplied by the drawing instead of by the glass. On the laptop the two are the same number, so everything passed; on the 4K table every finger landed at half of where it was, in the top left quarter of the table, and not one element of any table could be pressed: not a disc of the body, not a card of an object, not the button which starts a table.

The fingers are back in the pixels of the glass, which is the space a browser speaks: it is what `document.elementFromPoint` is asked in and what the box of an element is measured in. The two spaces cannot be confused again, because nothing hands a size over any more - the kit takes the window itself, and a table which tried to pass its drawing would not compile.

What a table is drawn in is unchanged: the scene of a table is still laid out in the pixels of the surface and scaled to the glass, so the picture of 0.2.2 is the picture of this release.

## Start again could not be pressed

Found while pressing every element of every table with a finger of the tracker: the note of an element was measured before it was told how wide it would be, so it was placed for a height it did not have. The note of **Start again** in the corner of the landing page was placed above the button and then grew down over it, and a finger resting on that button was resting on the note instead. The one button which hands the table to the next visitor was the one button a visitor could not press.

A note is now measured at the width it will have, so it stands where it was meant to stand.

## The table and the simulator are two apps

The simulator was part of the table: one command started both, the server of the application served the control page of the simulator and carried the tracker behind it, and the table of a booth was that same command with the simulator switched off. A table at an exhibition has no simulator in it, and a simulator is as good at driving an application of somebody else, so neither belongs inside the other.

```bash
npm run table       # the application, and the tracker it listens to
npm run simulator   # a tracker, and the surface which drives it
npm run dev         # one of each, which is this exhibition on a laptop
```

Each has settings of its own. The table takes the tracker of the booth and the ids of its pucks, the port it is served on and the table to open; the simulator takes its two ports, what it speaks, and the table it drives. `npm run dev` starts one of each, the simulator on 3333 and 3344 and the table on 5173, pointed at that tracker.

The server of the table carries the tracker of the table at `/tuio`, which is a setting of the table and the one place it is said, and nothing else: a page of a booth is an address with nothing in it, and a server which was given no tracker carries none and is driven by the mouse. The simulator is told where the table is, with `--table`, and its page opens that table under the surface by itself.

## The command of a booth is written down

[Run on a table](https://matthiaskoenig.github.io/pkpdsim-tui/table/) now opens with the quickstart of a booth: the one command, what it carries, and where everything listens.

```bash
npm install     # the repository, and the resources of this release
npm run table   # the table, the tracker it listens to and the ids of its pucks
# then open http://localhost:5173/
```

The tracker, the objects and the port of the table are a table of their own, as are the four ports of the two apps and which app each one belongs to. The documentation says `npm run sync` nowhere any more, because nothing of a table needs it.

## How this was checked

Every element of the landing page and of the four tables was pressed by a finger of the tracker, at 1920 by 1080 and at 3840 by 2160, in a browser which was given no touch event of its own, because that is what a real table is: 12 elements of the body and about 30 of each table, each one from the state the visitor meets it in. All of them press what they aim at at both sizes, and an object put on the glass, turned and lifted reads the same at both.
