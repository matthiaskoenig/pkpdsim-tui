# Release notes for pkpdsim-tui 0.1.0

First release of pkpdsim-tui, the tangible table applications of the PBPK/PD models of [pkpdsim](https://github.com/matthiaskoenig/pkpdsim). A visitor puts a physical object on a multitouch table and turns it, and the model answers: the pressure of the circulation changes, the liver grows back after an operation, the drug moves through the body, the machine keeps a liver alive. The objects are read over [TUIO](https://tuio.org/), the protocol of tangible surfaces, and the same application runs on a laptop with a mouse, so a table can be built, shown and taught without one.

## The tables

- **The circulation** (`?app=cardiovascular`, objects 1 to 3). The rate of the heart, how hard it squeezes and how open the vessels of the body are. The anatomy answers while a hand is still on an object: the pressures and flows of the organs come from an algebraic network solved as soon as something moves, and the beating heart beside it from the compiled model of pkpdsim.
- **Liver surgery** (`?app=lobes`, objects 1 and 2). An operation on the segments of the liver and how fast the remnant grows back, over the days after the resection.
- **A drug through the body** (`?app=glimepiride`, objects 1 to 6). The tablet and how fast it dissolves, the liver which takes the drug apart, the kidneys which wash it out, and how many mornings it is taken. The course of the drug runs on the clock of the table.
- **Machine perfusion** (`?app=perfusion`, objects 1 to 4). Flow, oxygen and temperature of a machine which keeps a liver outside a body, and the dial which walks through the hours of the run.

Every table is opened from one body on the landing page, and every table reads its objects from the markers 1 up, so the same pucks serve all four.

## The table itself

- **The objects.** A marker is a role of the model, its angle is the value, and the card beside it says what it is and what it reads. The band around an object shows how far it was turned from the body at rest, red up and blue down, with an arrow beside the number for a visitor who cannot tell the two colours apart. An object whose marker nothing claims is drawn as unassigned rather than ignored.
- **The glass.** No scrolling, no dialogs, nothing to click: a finger which rests on a switch presses it and fills while it does, and a finger which rests on a number, an organ or an object opens the sentence behind it. Everything a person reads stands upright for the side the panel is in.
- **The visitor.** The first screen asks the language, who is looking and who is at the table; the age, the weight and the height are chosen independently, a child starts at ten years, and every table is solved for that body. The choices travel in the address, so a booth opens on `?lang=es&level=child` and stays there.
- **The models.** Every model is compiled to WebAssembly and solved with SUNDIALS IDA in a Web Worker, so a solve never holds up the surface. The objects stay where they are while one runs, and what is on the table stays on it until the answer arrives.
- **A day without supervision.** A tracker which goes away is asked for again, after a second, then two, four and every eight. A table which could not start says one sentence to the visitor, keeps the reason for whoever looks after it, and loads itself again after twenty seconds.

## Languages and the voice

English, German and Spanish, each at three levels: for children, for grown ups and for specialists. Every word a visitor reads comes from the text module of its package rather than from the middle of a scene, and every sentence can be read aloud: 478 clips in English, 455 in German and 474 in Spanish, recorded with the neural voices of `piper-tts` by `npm run speech`.

## The simulator

`packages/tuio-simulator` is a tracker like a table is: a control page where objects are placed and turned with the mouse, and the TUIO stream behind it, in either version of the protocol and over WebSocket or UDP. `npm run dev` starts it with the application and serves both on one port, so the whole table is one address and a machine somewhere else is one forwarded port. The control socket takes only pages of the machine it runs on, because a page which reaches it decides what the table reads and where the tracker sends it.

## The package

- An npm workspace of twelve packages and one application: the input layer, the kit every table is drawn with, the compiled models and their ports, the four tables, and the simulator. Node 22 or newer, TypeScript throughout, built with vite.
- 308 tests with vitest, a type check of the whole tree, and a documentation build which fails on a broken link. The three run on every pull request.
- Documentation on [matthiaskoenig.github.io/pkpdsim-tui](https://matthiaskoenig.github.io/pkpdsim-tui): how to run it, the four tables, the simulator, how to set up a real table, the languages and the voice, and how the code is laid out.
