# Release notes for pkpdsim-tui 0.2.0

The release of the exhibition table: a clone of it is a table, the markers of a real table are its own, the whole of that table is said in one command, and a tap presses.

## A clone of a release is a table

Setting a table up read: clone, install, a pkpdsim checkout beside it for `npm run sync`, a glimepiride checkout for one export, uv and python for two more, piper-tts for the clips. 68 MB of what a table needs is written by those commands and is not in the repository, so a machine which was handed the repository could not start a table.

The resources travel with a release now, as two archives of the tag: the compiled models of the four tables with their runtimes and reference data, 4 MB, and the 2253 clips the tables read aloud, 49 MB. Each has a sha256 beside it, which is checked before anything is unpacked.

```bash
git clone https://github.com/matthiaskoenig/pkpdsim-tui.git
cd pkpdsim-tui
npm install     # and the resources of this release
npm run table
```

`npm install` takes the ones of the release the checkout is and says so, once. A checkout which has them says nothing. One which cannot reach the release says what to run rather than failing the install. CI takes nothing, because the checks of the repository open no model. `npm run assets` is the same said out loud, for a machine which was not on the network at install, and a table which cannot find a model of its own says that one command instead of the one of a developer with three checkouts.

What writes the models in the first place is unchanged: `npm run sync`, the two exports and `npm run speech` are what a release is packed from, with `npm run assets:pack`, which is now a step of a release.

## The table of a booth is said once

A table at an exhibition is a tracker on a machine of its own and a set of pucks with ids printed on them. Both were said in the address of every page, which meant they were said in every address anybody wrote down, and a page which was opened without them ran on the wrong tracker or read the wrong objects.

```bash
npm run table
# then open http://localhost:5173/
```

That is the whole of it, and it stands in `package.json`:

```bash
node scripts/dev.mjs --no-simulator --tuio 10.0.0.20:3343 --ids 1,3,5,6,11,12,21
```

The server is what knows the table. `--tuio` is where the tracker of the exhibition listens, which the server then carries at `/tuio`, so the browser only ever talks to the server and one forwarded port carries everything. `--ids` are the ids printed on the pucks, in the order the objects of a table are picked up. Every page that server serves is given both: the page a visitor is handed, the page a table opens again when a visitor walks away, and a page somebody typed. An address of a booth carries nothing at all, and `?tuio=` and `?ids=` remain as the override of a page which is not of a booth.

The panel, the title of the gear and the sentence a table shows while it waits name that tracker now, in all three languages, instead of the socket of the page itself: "Start a TUIO 2.0 tracker on 10.0.0.20:3343". A page of a booth waits for its table rather than looking once and settling for the mouse, because a table which is slow to answer is still the table.

## The objects of a table are read from the ids its markers carry

An application numbers its objects from 1 and a real table brings whatever was printed on its pucks. The ids of the table are now read at the edge of the application, so every table of the collection reads the markers of the table it is running on, and what a visitor is shown is the id of the puck in their hand: on the card of an object, in the panel, and in the sentence which asks for an object. A list which is no list of whole numbers, which names a puck twice, or which does not reach as far as the objects of a table is refused at the start rather than left to a visitor who turns an object nothing answers to.

## A tap presses

The table of the exhibition reports its fingers over TUIO and nothing else: Chrome sees no touch on the glass, so the only way to press anything was to rest a finger on it for 620 ms. A visitor taps, as they do on a phone, and the table did not answer, which was most of the UI not reacting to touch.

A finger which lands on an element and goes again presses it when it goes; a finger which stays presses it after the fill, as before. A finger which moved off the element before it went presses nothing, and neither does a hand sweeping across the glass or leaning on it. One press serves the whole application now, so the speakers of the first screen, the "read this aloud" of a visitor who cannot read the language, can be pressed by a finger at all; they had their own loop which read only the cards beside them. The mouse of a laptop presses once, not twice: the page sends its click and the finger it stands for no longer sends a second one.

Everything a finger presses is at least 44 pixels in both directions, measured on every screen. The speaker of the body was 34, the way back and the switch of the species 35: a visitor aims by eye across a table rather than with a pointer.
