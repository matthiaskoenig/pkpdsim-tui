# Release notes for pkpdsim-tui 0.1.1

A release of fixes: a table which cannot find its models now says which file is missing and which command writes it, and the whole of it starts on Windows as well as on Linux and macOS.

## A table which cannot find its models

The exported models and reference data are not in the repository, and the three commands which write them are the first thing a new checkout runs. All three ways that could go wrong said nothing useful:

- **`npm run sync` was all or nothing.** A pkpdsim checkout which is behind the export the tables ask for stopped the script before it copied anything, not even the complete export of another table beside it. One incomplete export now stops that table alone, and what is missing is named with both ways out of it: the checkout which is behind, and the checkout which never wrote the export.
- **A missing file was answered with the page.** The development server and the preview of the build answer a path they do not know with `index.html` and a 200, because the application is one page, so every check of the loaders was passed and a model arrived as a page of HTML. The parser then reported an unexpected character of that page, which named neither the file nor the command. The folders of `public` which hold files and never a page answer a 404 now, and a body of HTML where a model was asked for is said to be the missing file it is wherever a table is served.
- **The command was the wrong one for two of the four tables.** The drug and the machine perfusion tables are written by `npm run export:glimepiride` and `npm run export:perfusion`, not by `npm run sync`, and the quick start named neither. The sentence a table fails with names the command of its own folder, and all three stand in the readme, in the documentation and in the deployment of a tag.

## The table on Windows

`npm run dev` did not start on Windows at all: the launcher spawned the shim of `node_modules/.bin`, which is no program under its plain name there. vite is started as the script it is now, with the node which is running, like the simulator always was. The two commands which compile a model asked a shell to expand a default path, which `cmd.exe` reads literally and hands to python as the name of a model; the path stands in the command now, and a model somewhere else is given as `npm run export:perfusion -- --sbml <path>`, which every shell reads the same way and which replaces the two environment variables of the documentation.

A `windows` job runs the checks of `node` again on Windows, so the next command which works on only one kind of machine is seen on a pull request rather than when a table is unpacked. It found two more things on its first run: the 404 answer above normalised the path of a request as a path of the platform, which recognised none of the folders of data on Windows, and the test of the release notes read the first line by splitting on a newline, which leaves the carriage return of a checkout there. A `.gitattributes` keeps one line ending in every checkout, which is what the exported models, the recorded clips and the pages are fingerprinted on.

## The release itself

The `sync-main` job names `refs/heads/main` in full, so the fast-forward of `main` creates the branch when a repository has not had a release yet.

## The package

332 tests with vitest, a type check of the whole tree, and a documentation build which fails on a broken link, all three on Linux and on Windows on every pull request.
