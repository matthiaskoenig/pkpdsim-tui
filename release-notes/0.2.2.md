# Release notes for pkpdsim-tui 0.2.2

The table of the exhibition is 4K and the laptop these tables are written on is not. Everything is drawn on one surface now, 1920 by 1080, and scaled to the glass it is shown on, so both show the same picture.

## The same picture on every glass

A table was half the size on the 4K table: the panel, the cards, the brief and the buttons measured exactly half of what they measure on a laptop, and a scene drawn in the pixels of the window kept its plots at the size they had on a 1K screen and capped them there. A visitor at the table read a quarter of the glass.

The size of the surface in front of the visitor is now said in one place, the stylesheet, as the size of the text of the page, and everything is a multiple of it. The page itself grows with that text, and every table lays its scene out in the pixels of the surface rather than of the window, so the browser scales the lines, the text and the layout of it together. The 4K table draws the same picture at twice the size: the same panel in the same corner, the same cards beside the objects, the same lines of the same thickness.

Nothing is set for this and there is no setting to get wrong. A window of another shape is laid out for the shape it has rather than stretched, and nothing is let below ten pixels of text, so a window somebody opened beside the simulator is small rather than unreadable. The chrome of the simulator scales the same way.

Measured in a browser at 1920 by 1080 and at 3840 by 2160, on the body, the four tables, the first screen and the page about all of this: every element is within two percent of the same part of the surface at both, and the drawing of a scene is the same 1920 by 1080 at both.

## What the documentation says a table needs

A table is a clone, an install and `npm run table`, which is what 0.2.0 made true, so the documentation no longer tells anybody to write the models first. `npm run sync` and the two export commands are named in one place, The resources of a release, which is for whoever cuts the next one; everywhere else says where the models and the clips come from and nothing to run. The clips are the same: they travel with a release rather than being recorded by a fresh clone.

What TUIO is has gone with it. The protocol belongs to [tuio.org](https://tuio.org/), and the one part of that page which was of this repository, what the input layer takes of TUIO 2.0 and the turn it adds, is now part of the input layer itself.

The full screen of a booth was also out of date: it served the build on another port with the tracker written into the address. The tracker and the ids belong to the server, so it is `npm run table -- --preview` on the one port of the table, and the address of the kiosk carries nothing.

## The package

388 tests with vitest, a type check of the whole tree, and a documentation build which fails on a broken link, all three on Linux and on Windows on every pull request. The resources of the table, the compiled models and the clips, are the two archives of this release, which an install takes.
